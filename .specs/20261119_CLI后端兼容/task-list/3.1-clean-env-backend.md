# 3.1 cleanEnv 双前缀/按后端开关 + env-probe fixture

- 所属任务组：T3. 环境清理与记忆开关
- 硬前置：1.1

## 目标

`cleanEnv` 剥离 `QODER_*` 与 `QODERCN_*` 双前缀（及既有 CLAUDECODE / CLAUDE_CODE_*），memory=true 时按后端画像设对应记忆开关且互斥；`runQoder` 把 bin 传给 cleanEnv。新增 fixture `env-probe` 模式坐实子进程实际收到的 env。调用层 args/解析/超时零改动。

## 实现要点

- `src/bridge/qoder.ts` `cleanEnv(opts: { memory?: boolean; bin?: string } = {})`：剥离条件加 `key.startsWith('QODERCN_')`；`if (opts.memory) env[backendProfile(opts.bin ?? 'qodercli').memoryEnv] = '1'`（D3：bin 缺省 intl，既有调用方与单测零改动获得双剥）。
- `runQoder` 内唯一改动：`env: cleanEnv({ memory: input.memory, bin: input.bin })`（qoder.ts:206）。
- 更新 cleanEnv JSDoc：说明双前缀原因（CN 桌面 shell 可能注入 QODERCN_*）与 CN 记忆开关来源（yo() 实测）。
- `test/fixtures/fake-qodercli.mjs` 增 `env-probe` 模式：result.result 内嵌 JSON `{intl: QODER_MEMORY_HEADLESS ?? null, cn: QODERCN_MEMORY_HEADLESS ?? null, leaked: 残留 QODER_*/QODERCN_* 键列表}`，session_id 's-env'。
- 先写失败用例：`test/unit/qoder.test.ts` 追加 cleanEnv 单测（注入 QODER_X/QODERCN_Y/CLAUDECODE/CLAUDE_CODE_Z 断言全剥；memory × intl/cn 开关互斥；memory=false 两个都不设；bin 缺省按 intl）；runQoder 用 cross-spawn mock 捕获 options.env 断言按 bin 设开关（照 qoder-name.test.ts fakeChild 范式）；env-probe 夹具集成断言（可放 qoder.test.ts 真实 spawn 夹具路径）。
