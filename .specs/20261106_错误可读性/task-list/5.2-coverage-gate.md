# 5.2 覆盖率门禁、全量回归与构建校验

- 所属任务组：T5. 集成与门禁
- 硬前置：5.1

## 目标

把两个新增文件纳入覆盖率门禁，跑通全量回归与发布前校验，并把版本号提到 `0.3.0`。

**关键设计决策**：`vitest.config.ts` 的 `coverage.include` 是**白名单**，新增的 `error-class.ts` 与 `error-dedup.ts` 不显式追加就**不会被统计**——覆盖率数字看起来照样达标，但两个核心纯模块实际处于门禁之外。这一步不能省。

**边界条件**：一期基线为 214 tests / Lines 97.44%，本期结束后测试数应显著增加且 Lines 仍 ≥ 95%。

## 实现要点

- 修改 `vitest.config.ts`：在 `coverage.include` 数组中追加 `'src/bridge/error-class.ts'` 与 `'src/bridge/error-dedup.ts'`；`thresholds.lines` 保持 `95` 不变；`exclude` 与其余配置不动。
- 修改 `package.json`：`version` 由 `0.2.0` 改为 `0.3.0`。**不新增任何依赖**（`vitest` / `@vitest/coverage-v8` / `fast-check` 一期已就位）。
  - 版本依据：无破坏性变更（`QoderRunResult` / `buildUserErrorReply` / `DiagnosticInput` 的新增字段全部可选），但改变了用户可见的错误文案与下行条数，按语义化版本属 minor。
- 依次执行并收集输出：全量单测 + 覆盖率 → 类型检查 → 构建 → 发布前校验。
- 若覆盖率未达 95%，**回到对应模块的单测子任务补用例**（1.1 / 1.2 / 2.1 / 2.2 / 3.1 / 3.2 / 4.1 / 4.2），不得通过调低 `thresholds` 或把文件移出 `include` 白名单来"达标"。
- 本子任务**不改** README / RUNBOOK：文档同步（设计 11.3）按 jojo-specs 阶段约束排除在任务清单外，实现完成后由用户决定是否补。
