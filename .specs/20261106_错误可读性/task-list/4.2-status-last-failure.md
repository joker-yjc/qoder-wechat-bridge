# 4.2 status 新增"最近失败"行

- 所属任务组：T4. 编排与可观测
- 硬前置：1.1、2.2

## 目标

让本机运维者不翻日志就能知道最近一次失败的类别与发生时间（需求 4.1），且与既有"下行额度"行在字面和字段名上都不混淆（需求 4.4）。

**关键设计决策**：`status` 只显示语义类别的中文 label + class 名 + `error_code` + 退出码 + 时间 + taskId，**不显示传输层 `kind`**。`kind` 已在日志与诊断文件里，status 只回答需求 4.1 问的"类别与时间"，保持单行简短。

## 实现要点

- 修改 `src/status.ts`：
  - 从 `./bridge/error-class.js` 导入 `ERROR_CLASS_LABEL`。**不**从 `bridge/failure.js` 导入，避免顶层模块反向依赖桥接层文案模块。
  - 在 `quotaLine` 之后计算 `lastFailureLine`：
    - `state.lastFailure` 为 `null` → `最近失败：无`
    - 否则 → `最近失败：{label}（{errorClass}｜error_code={errorCode}｜退出码 {exitCode}）于 {本地时间}｜任务 {taskId}`
    - `errorCode` 缺失时**整段省略**（含前面的 `｜`），不输出 `error_code=undefined`
    - `exitCode` 为 `null` 时显示 `未知`（与 `failure.ts` 的既有约定一致）
    - 时间格式沿用 `quotaLine` 的写法：`new Date(at).toLocaleString('zh-CN', { hour12: false })`
  - 返回数组在 `quotaLine` 之后追加 `lastFailureLine`，既有 14 行全部保留且顺序不变。
- **需求 4.4 的落地点**：`下行额度：…`（既有，微信 `ret=-2`）与 `最近失败：…`（本期，含 `model_quota`）两行的文案前缀、字段名均不重叠；`ERROR_CLASS_LABEL.model_quota` 是"模型额度已用尽"，与 `quotaLine` 的"下行额度"字面可区分。**不得**把两者合并成一行，也不得复用 `quota` 这个词描述模型额度。
- 单测委托 `unit-test` skill，覆盖设计 8.2 的 `status.ts` 行。

## 验收标准

- `src/status.ts` Lines 覆盖率 ≥ 95%。
- `lastFailure` 为 `null` 时输出 `最近失败：无`。
- `lastFailure` 完整时输出含 label、`errorClass`、`error_code`、退出码、时间与 taskId 六个片段，格式与设计 3.2 的示例一致。
- `errorCode` 缺失时该行不含 `error_code=` 字样，且无多余 `｜`。
- `exitCode` 为 `null` 时显示 `退出码 未知`。
- 四个 `errorClass` 各自映射到正确 label；`unknown` 显示"未归类"。
- 同一份 state 同时含 `quota.streak > 0` 与 `lastFailure.errorClass='model_quota'` 时，输出**两行独立**且字面可区分（需求 4.4 的核心断言）。
- 一期用例全部保持绿：既有 14 行的内容与顺序、`formatBytes` / `formatAge`。
