# 4.3 库入口导出新增类型与函数

- 所属任务组：T4. 编排与可观测
- 硬前置：1.1、1.2、2.1、2.2

## 目标

把本期新增的模块与类型接入 `src/index.ts`，保持库形态（CLI + 可编程调用双入口）的对外契约完整。

**关键设计决策**：`index.ts` 集中在本子任务一次改完，而不是让每个新增模块的子任务各自追加——避免同一文件被多个子任务写入而产生冲突。全部新增导出均为**向后兼容**（新函数 / 新类型 / 既有函数的可选入参），无破坏性变更。

## 实现要点

- 修改 `src/index.ts`，按既有分组风格追加：
  ```ts
  export { classifyQoderError, ERROR_CLASS_LABEL } from './bridge/error-class.js';
  export type { QoderErrorClass, QoderErrorClassification, QoderSemanticFields } from './bridge/error-class.js';

  export { ErrorDedupStore } from './bridge/error-dedup.js';
  export type { ErrorDedupDecision, ErrorDedupOptions } from './bridge/error-dedup.js';

  export { buildAckText, ACK_MAX_CHARS } from './bridge/failure.js';
  ```
- `buildUserErrorReply` / `truncateGraphemes` / `QoderErrorKind` 一期已导出，签名扩展为可选入参，**导出语句不需要改动**。
- `src/config.js` 的既有导出块中追加 `LastFailureRecord` 到 `export type { … } from './config.js'` 列表（按字母序插入，与既有风格一致）。
- 位置安排：`error-class` / `error-dedup` 紧跟既有的 `bridge/failure.js` 导出块之后，保持"桥接层集中"的现有排列。
- 每个新增导出块前如有必要补一行中文分组注释，风格对齐既有的 `/** 微信通道能力（收发消息、扫码状态、typing） */`。
- 本子任务**不新增单测**：现有 `test/unit/smoke.test.ts` 只有 8 行、仅测 `chunkText`，**不**断言导出清单也不 import `index.js`，因此本期无既有测试会因导出变化而失败；导出正确性由 `npm run typecheck` + `npm run build` 保证。`src/index.ts` 也不在 `vitest.config.ts` 的 `coverage.include` 白名单内，无覆盖率门禁。

## 验证命令

```bash
npm run typecheck && npm run build && node -e "import('./dist/index.js').then(m=>{const need=['classifyQoderError','ERROR_CLASS_LABEL','ErrorDedupStore','buildAckText','ACK_MAX_CHARS'];const miss=need.filter(k=>!(k in m));console.log(miss.length?'缺失导出: '+miss.join(','):'新增导出全部就位 ✓')})"
```

## 验收标准

- `npm run typecheck` 通过，无新增类型错误。
- `npm run build` 成功产出 `dist/`。
- 上述 `node -e` 检查输出 `新增导出全部就位 ✓`，即 `dist/index.js` 实际导出 `classifyQoderError`、`ERROR_CLASS_LABEL`、`ErrorDedupStore`、`buildAckText`、`ACK_MAX_CHARS`。
- `LastFailureRecord` 作为类型导出，由 typecheck 覆盖（运行时不可见，属预期）。
- 一期已导出的全部符号仍然存在（无意外删除）：`buildUserErrorReply`、`truncateGraphemes`、`runQoder`、`OutboundSession`、`buildStatusLines` 等仍可解析。
