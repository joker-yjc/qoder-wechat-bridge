# 5.1 端到端复现两次事故与去重行为

- 所属任务组：T5. 集成与门禁
- 硬前置：4.1、4.2、4.3

## 目标

用假 iLink HTTP 服务 + 假 qodercli 脚本跑通完整链路，把两次真实事故变成可重复执行的回归用例，并验证去重、ack、不入队、续接降级与 `status` 输出。

**关键设计决策**：fixture 的 JSON 结构**直接取自真实诊断文件**（`~/.local/state/qoder-wechat-bridge/logs/diagnostics/2026-11-05/`、`.../2026-11-06/`），不是手写近似值——这样"复现事故"这句话是有证据支撑的，而不是自说自话。

**边界条件**：不调用真实微信通道、不调用真实 qodercli、不写用户真实 state 目录（沿用既有集成测试的临时目录注入方式）。

## 实现要点

- 修改 `test/integration/fake-ilink.test.ts`，沿用一期已有的假 iLink HTTP 服务与 `test/helpers/fake-ilink.ts`，新增以下场景（对应设计 8.4 的表）：
  1. **复现 11-05 额度刷屏**：`FAKE_QODER_MODE=quota-110`，连发 5 条入站消息 → 断言用户收到 **1 条完整提示 + 4 条 ack**；完整提示含"模型额度已用尽"；4 条 ack 的 `suppressed` 依次为 1/2/3/4；`state.outbox` 与 `state.quarantine` 长度均为 0；日志含 4 条 `category=suppressed`；`state.lastFailure.errorClass === 'model_quota'` 且 `errorCode === '110'`。
  2. **复现 11-06 输出截断**：`FAKE_QODER_MODE=max-output-tokens` → 断言 `ok=false`、下行 1 条含"回答被截断"、**不含**任何英文原文、诊断文件 header 含 `# errorClass: output_limit`。
  3. **凭据失效**：`auth-failed` → 提示含"凭据已失效"与"在本机"，不含 `authentication_failed` 字样。
  4. **未归类语义错误**：`semantic-unknown` → 提示为一期 `exit` 文案；日志含 `未识别的 qodercli 语义错误` 且 `errorCode === 'rate_limit'`。
  5. **跨类别不抑制**：先 `quota-110` 再 `max-output-tokens` → 两条都是完整提示。
  6. **窗口过期**：注入时钟推进 `windowMs + 1` 后再 `quota-110` → 重新收到完整提示，且后续 ack 的 `suppressed` 从 1 重新开始。
  7. **提示发送失败**：假 iLink 对错误提示返回 `ret=-2` → 不 commit、不入队、写 `错误提示未送达，不推进去重窗口` 告警；下一次同类失败仍发完整提示。
  8. **续接降级**：`resume-failed` + 既有 `sessionId` → 触发新建会话重试；重试成功则 `lastFailure` **不**写入。
  9. **`status` 输出**：上述任一失败后调用 `buildStatusLines` → 输出同时含"最近失败："与"下行额度："两行，且两行字面可区分。
  10. **一期回归**：一期全部集成用例（261KB stderr、第一条永久失败后两条正常、连续 `ret=-2` 补发、`ret=-14` 停循环、过期/超限丢弃、重启后隔离区不回流、预检失败）保持绿。
- 断言下行条数时按 `kind === 'error'` 过滤假 iLink 收到的消息，避免把 typing / 命令回复计入。
- 时钟注入：场景 6 需要可控时间，沿用 service 已有的 `now` 注入点；不要靠 `setTimeout` 真等 10 分钟。
