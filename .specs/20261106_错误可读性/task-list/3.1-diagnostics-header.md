# 3.1 诊断文件 header 增加语义字段

- 所属任务组：T3. 采集与落盘
- 硬前置：1.1

## 目标

让诊断文件在记录传输层 `kind` 的同时记录业务语义类别与 `error_code`，使事后排查不必再从 stdout 里手工翻 JSON。

**关键设计决策**：`kind` **保留传输层语义**（`exit` / `is_error` / `timeout` …），新增两行承载业务语义，两者不互相覆盖。排查时都需要：`kind` 说明进程怎么失败的，`errorClass` 说明 qodercli 报的是什么。

**边界条件**：新增字段为可选，缺失时写空值（与既有 `# sessionId:` / `# exitCode:` 的处理一致），不能让 3.2 之前的调用方编译失败。

## 实现要点

- 修改 `src/diagnostics.ts`：
  - `DiagnosticInput` 新增两个可选字段：`errorClass?: string`、`errorCode?: string`。用 `string` 而非 `QoderErrorClass`，避免 `diagnostics.ts` 反向依赖 `bridge/error-class.ts`（一期已让本文件依赖 `bridge/failure.js` 取 `QoderErrorKind`，不再扩大耦合面）。
  - `header` 数组在 `# kind:` 之后、`# exitCode:` 之前插入两行：
    ```
    # errorClass: model_quota
    # errorCode: 110
    ```
    缺失时写 `# errorClass: ` / `# errorCode: `（尾部留空，与既有风格一致）。
  - 字节预算逻辑**不改**：现有实现已用 `maxBytes - Buffer.byteLength(header)` 计算 `remaining`，header 变长会自动挤压 stdout/stderr 预算，无需额外处理。
- 一期行为**不变**：脱敏（`redactSensitive`）、`truncateBytes`、stdout/stderr 动态分配与回补、`0700` 目录 / `0600` 文件权限、写失败返回空路径、`pruneDiagnostics` 全部保持。
- 单测委托 `unit-test` skill，覆盖设计 8.2 的 `diagnostics.ts` 行。

## 验收标准

- `src/diagnostics.ts` Lines 覆盖率 ≥ 95%。
- 传入 `errorClass` / `errorCode` 时，header 第 4、5 行为 `# errorClass: …` / `# errorCode: …`，且 `# kind:` 仍在其前。
- 两字段缺失时写出空值行，不产生 `undefined` 字样。
- 总字节数仍 ≤ `maxBytes`（默认 64KB）；header 变长后 stdout/stderr 预算相应收缩且不产生无效 UTF-8。
- 一期用例全部保持绿：脱敏命中 `Bearer` / `sk-` / `token=`、`0600` 权限、写失败返回 `{ path: '', bytes: 0 }`、`pruneDiagnostics` 按 mtime 清理并删空目录。
