# 1.2 去重窗口决策与计数（含属性测试）

- 所属任务组：T1. 语义分类与去重（纯逻辑）
- 硬前置：1.1

## 目标

实现"窗口内同类错误只发一条完整提示、其余发 ack"的决策与计数逻辑，作为可穷举测试的纯组件。

**关键设计决策 1：状态放内存，不放 `state.json`。** 窗口只有 10 分钟、失败全部由用户入站触发；持久化会带来 schema 迁移与状态膨胀，收益极低。重启后窗口重置的最坏结果是**多发一条完整提示**——失败方向安全（宁可多提示，不可静默吞掉）。

**关键设计决策 2：`plan()` / `commit()` 分离，而非合成一个 `take()`。** 目的是让"发送失败不推进窗口"（需求 3.4）在调用点显式可见，而不是隐藏在存储内部。若发送失败也计数，用户会在整个窗口内什么都收不到。

**边界条件**：时钟通过参数注入，模块内**不**直接调用 `Date.now()`；不发消息、不写日志、不落盘。

## 实现要点

- 新增 `src/bridge/error-dedup.ts`，导出：
  - `interface ErrorDedupDecision`（`full: boolean`、`firstAt: number`、`suppressed: number`）
  - `interface ErrorDedupOptions`（`windowMs: number`、`now?: () => number`）
  - `class ErrorDedupStore`，方法 `plan(userId, errorClass)` / `commit(userId, errorClass, full)` / `get size()`
- 内部状态：`Map<string, { firstAt: number; suppressed: number }>`，key 为 `` `${userId}\u0000${errorClass}` ``——用 NUL 分隔，避免 `userId` 含冒号时产生歧义。
- **`plan` 算法**（只读，不改状态）：
  1. `pruneExpired()`：遍历 Map，删除 `now - firstAt >= windowMs` 的条目
  2. 取 entry；不存在（含刚被 prune 掉）→ `{ full: true, firstAt: now, suppressed: 0 }`
  3. 存在 → `{ full: false, firstAt: entry.firstAt, suppressed: entry.suppressed + 1 }`
- **`commit` 算法**：`full === true` → `set(key, { firstAt: now, suppressed: 0 })`；`full === false` → `get(key).suppressed += 1`。
- `commit(full=false)` 时 entry 必然存在：`plan` 只在 entry 存在且未过期时返回 `full=false`，而 `plan` 与 `commit` 之间只有 `await sendSingle`，期间同一 `userId` 不会有并发调用（见 4.1 的并发说明）。**因此不写 entry 缺失的兜底分支。**
- **`suppressed` 语义**：`plan` 返回的是"含本次在内的累计抑制次数"（`entry.suppressed + 1`），ack 文案直接使用该值，不需要调用方再 +1。
- **Map 有界性**：条目上界 = 授权用户数 × 4；每次 `plan` 都 prune，不会无界增长。
- **时钟回拨**：判定式 `now - firstAt >= windowMs`，回拨时差值变小或为负 → 窗口被延长，最坏多发几条 ack；不会误判过期而重复发完整提示，不抛异常。与一期 outbox TTL 的处理方向一致。
- 属性测试用 `fast-check`（一期已有的 devDependency，**不新增依赖**）：生成随机 `(userId, errorClass, timestamp, sendOutcome)` 序列（时间戳单调递增），断言任一 `windowMs` 长度窗口内每 `(userId, class)` 完整提示 ≤ 1 条、未送达不推进状态、过期后重新完整提示。
- 单测委托 `unit-test` skill，覆盖设计 8.2 的 `bridge/error-dedup.ts` 行；全部用例通过注入时钟驱动，**不依赖真实时间**。

## 验收标准

- `src/bridge/error-dedup.ts` Lines 覆盖率 ≥ 95%。
- 首次失败 `full=true` 且 `suppressed=0`；窗口内第 2 次 `full=false` 且 `suppressed=1`；第 n 次 `suppressed=n-1`。
- 只调用 `plan` 不调用 `commit` 时，状态不变（连续 `plan` 返回相同结果）。
- 窗口过期（推进 `windowMs` 后）重新 `full=true` 且 `suppressed` 归零。
- 不同 `errorClass` 互不抑制；不同 `userId` 互不抑制。
- 时钟回拨用例不抛异常，且不产生"误判过期后重发完整提示"。
- 属性测试断言"任一窗口内每 key 完整提示 ≤ 1 条"在随机序列下成立。
