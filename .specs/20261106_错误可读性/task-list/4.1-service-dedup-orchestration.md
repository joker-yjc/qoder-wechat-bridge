# 4.1 service 去重编排、续接降级迁移与不入队

- 所属任务组：T4. 编排与可观测
- 硬前置：1.2、2.1、2.2、3.2

## 目标

把语义分类、去重、ack、`lastFailure` 与"错误提示不入队"接进 `processTask`，并修掉一处会静默失效的既有耦合。

**关键设计决策 1：`ErrorDedupStore` 必须放在 `runService` 作用域。** `processTask` 内的 `OutboundSession` 是**每轮新建**的，无法承载跨轮状态。store 与 `state` 同级创建，`now` 复用 service 已有的注入时钟，保证去重与 outbox TTL 用同一时间源。

**关键设计决策 2：只有 `outcome === 'sent'` 才 `commit`。** 发送失败也计数会让用户在整个窗口内什么都收不到。这与需求 3.4「发送失败只写日志」一致，且失败方向安全。

**关键设计决策 3（必须做的隐患修复）：续接降级正则从 `result.error` 迁到 `result.errorDetail`。** `src/bridge/service.ts:591` 现在匹配 `result.error` 里的英文原文；3.2 之后 `error` 只含中文模板，该正则将**永久静默失效**，且当前无任何测试覆盖。迁移后命中面比改造前更宽（`errors[0]` / `error_message` 也参与匹配），是行为增强而非退化。

**并发说明**：同一 `userId` 的任务由 `runningTasks` 与入站串行化处理保证不并发；不同 `userId` 并发时 key 不同，互不干扰。因此 `plan` → `await sendSingle` → `commit` 之间不存在同 key 竞态。

## 实现要点

- 修改 `src/bridge/service.ts`：
  1. **持有 store**：在 `runService` 内与 `state` 同级创建
     `const errorDedup = new ErrorDedupStore({ windowMs: config.errorDedupWindowMs, now });`
  2. **续接降级迁移**（第 591 行附近）：正则的匹配源由 `result.error ?? ''` 改为 `result.errorDetail ?? ''`，判定条件其余部分（`!result.ok && record?.sessionId`）不变；`log.warn('续接会话失败，改为新建会话重试', …)` 的字段由 `error` 改为 `errorDetail: result.errorDetail?.slice(0, 160)`，并补 `errorClass` / `errorCode` / `taskId`。
  3. **写 `lastFailure`**：插在续接降级重试**之后**、`log.info('任务结束')` **之前**，确保记录的是**最终**结果（重试成功则不记失败）：
     ```ts
     if (!result.ok) {
       state.lastFailure = {
         kind: result.errorKind ?? 'exit',
         errorClass: result.errorClass ?? 'unknown',
         errorCode: result.errorCode,
         exitCode: result.exitCode ?? null,
         at: now(),
         taskId: id,
       };
       persistState();
     }
     ```
  4. **`任务结束` 日志补字段**：追加 `errorClass: result.errorClass ?? ''`、`errorCode: result.errorCode ?? ''`、`diagnosticPath: result.diagnosticPath ?? ''`（`sessionId` / `taskId` / `exitCode` 一期已有）。一期字段全部保留。
  5. **未识别语义错误告警**（需求 1.7）：
     ```ts
     if (!result.ok && result.errorClass === 'unknown' && (result.errorCode || result.errorDetail)) {
       log.warn('未识别的 qodercli 语义错误', {
         errorCode: result.errorCode ?? '',
         errorSummary: redactSensitive(result.errorDetail ?? '').slice(0, 160),
         taskId: id,
       });
     }
     ```
     `redactSensitive` 从 `../diagnostics.js` 导入（一期已导出），满足 N2。
  6. **错误提示发送改为去重 + 不入队**（替换原第 645 行的单行 `sendSingle`）：
     - `errorClass = result.errorClass ?? 'unknown'`
     - `decision = errorDedup.plan(userId, errorClass)`
     - `body = decision.full ? (result.error ?? buildUserErrorReply({ kind, errorClass, exitCode, maxChars: config.userErrorMaxChars })) : buildAckText({ errorClass, firstAt: decision.firstAt, suppressed: decision.suppressed })`
     - `outcome = await session.sendSingle(body, { kind: 'error', queueOnFailure: false, taskId: id })` —— **`queueOnFailure` 由 `true` 改为 `false`**，这是需求 3.1 的落地点
     - `outcome === 'sent'` → `errorDedup.commit(userId, errorClass, decision.full)`；否则 `log.warn('错误提示未送达，不推进去重窗口', { userId, taskId: id, errorClass, outcome, suppressed: decision.suppressed })`
     - `!decision.full` → `log.info('错误提示被去重窗口抑制', { category: 'suppressed', userId, taskId: id, errorClass, suppressed: decision.suppressed, firstAt: decision.firstAt })`。**抑制日志与 `outcome` 无关**：即使 ack 未送达也如实记录本次被抑制（需求 4.3）。
  - 保留 `result.error ?? buildUserErrorReply(…)` 的兜底写法（一期既有防御），只在其入参里补 `errorClass`。
- **不改**的部分：`/help` `/status` `/reset` `/model` `/stop` 命令分支、`sendChunked` 正常回复路径、`flushForUser` 补发、`TypingKeeper`、outbox / 隔离区逻辑、`notify` 路径——它们的 `queueOnFailure: true` **保持不变**，本期只收紧错误提示。
- `/reset` **不清去重条目**：`/reset` 的语义是重置 qodercli 上下文，与"错误提示是否刷屏"无关；用户 `/reset` 后立刻又撞上同类错误，仍应走 ack。
- 单测委托 `unit-test` skill，覆盖设计 8.2 的 `bridge/service.ts` 行；沿用既有 `service.test.ts` 的 fake 依赖注入方式（`runQoderFn` / `sendTextFn` / `now`）。

## 验收标准

- `src/bridge/service.ts` Lines 覆盖率 ≥ 95%。
- 错误提示以 `queueOnFailure: false` 发送：发送异常 / 下行额度耗尽 / 会话过期三种情况下 `state.outbox` 与 `state.quarantine` 长度均为 0。
- 连续 5 次同类失败：第 1 次发完整提示，第 2–5 次发 ack 且 `suppressed` 依次为 1、2、3、4；日志含 4 条 `category=suppressed`。
- `outcome !== 'sent'` 时 `commit` 未被调用，下一次同类失败仍发完整提示。
- 不同 `errorClass` 先后出现时各自都发完整提示（互不抑制）。
- `lastFailure` 在最终失败时写入且字段完整；续接降级重试成功时**不**写入；任务成功时保留上一次记录不被清空。
- **续接降级仍生效**：`errorDetail` 含 `resume not found` 且存在既有 `sessionId` 时触发新建会话重试（用 3.2 的 `resume-failed` fixture 或等价 mock）。
- `unknown` + 有语义字段时写出 `未识别的 qodercli 语义错误` 告警，且 `errorSummary` 已脱敏并截断到 160 字。
- 一期用例全部保持绿：outbox 补发优先、毒丸隔离、`ret=-2` 停本轮、`/stop`、启动清理、预检告警。
