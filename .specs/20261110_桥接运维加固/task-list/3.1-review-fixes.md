## 目标

按 `review.md` 第一轮审查结论，修复 5 条 Block、7 条验收欠账与文档问题，使实例互斥在 launchd 重启重叠、调试双开、升级窗口三类场景下都不再制造双写。

## 实现要点

- **B1 释放时机**：`handle.stop()` 与信号退出都先 `cancelAllTasks()` + `waitForIdle()` 排空（上限 3s，共享同一个 drain promise），再清 `run.json`、释放锁；主循环 catch 在 `!running` 时立即退出，不再空等退避。
- **B2 跨进程证据**：新增 `test/fixtures/instance-lock-contender.mjs`（Vite SSR 加载 TS），集成用例 spawn 两个真实子进程抢同一状态目录，断言恰好一个成功；同进程用例改名注明只测防重入。
- **B3 接管方向**：只有 `!alive(pid)` 才允许接管；存活但命令行不匹配按占用等待并记 error。`isBridgeCommand` 支持 `node --inspect`、`env node`、`npm exec` 等前缀形态，同时保留 shell 包装防线。
- **B4 忙等**：`missing` 分支到达 deadline 抛 `LockIoError(EBUSY)`。
- **B5 测试隔离**：集成用例把 `HOME` 指向临时目录，断言注册表目录无残留。
- **R1 可观测性**：拒绝启动与命令行不匹配都 `log.error` 记录自身 pid、对方 pid、判定依据、锁路径；脏锁接管保持 warn。
- **R2 文案**：`describeOwner` 输出启动时间与工作目录，缺失显示 `(未知)`。
- **R3/R5 错误与指标**：`LockIoError` message 含路径；`waitedMs` 为实际等待时长。
- **R4 等待预算**：两阶段取锁共享同一 `deadline`，总等待不超过 5s。
- **R6 异常释放**：runtime / 预检 / `writeRunInfo` 纳入启动 try，异常时释放锁并摘信号监听。
- **R7 降级告警**：`botId` 为空时 warn，明确跨目录互斥不可用。
- **D1 升级窗口**：无锁但 `run.json` 指向存活桥接进程时拒绝启动；陈旧则清理后继续（`run.json` 不再只是记录，而是无锁实例的兜底判定源）。
