# 4.1 第二轮审查问题修复

- 所属任务组：T4. 第二轮审查修复
- 硬前置：3.1

## 目标

收口复审唯一 Block（drain 超时释放锁），并清掉 7 条 Important、Minor 与 5 条文档口径冲突。

## 实现要点

- **B1 残余**：runtime 注入 `isStopping()` 与 `canPersist()`；入站两处门禁；`shutdown()` 排空失败**保留锁**并记 error；`stop()` 等 `runLoop` 收敛；会话过期/循环异常不取消任务（保留 outbox 写入），用户停止才取消；新增「任务超过排空上限」用例。
- **I-1**：`AlreadyRunningError` 增加 `lockFile`；CLI 拒绝时额外输出 `rm "<lockFile>"` 人工处置命令；不做按时间自动接管，设计风险表写明取舍。
- **I-2**：不改行为，在设计属性 9 说明 `run.json`（提示源）与锁（权威源）判定方向不同的理由。
- **I-3**：`missing` 分支补 `await sleep(pollMs)`。
- **I-4**：bot 锁 deadline 在登录结束后重新计算，需求 4.2 改为「每把锁 5s」。
- **I-5**：`createLock` 改为写临时文件 + `link(2)`，短写 `ENOSPC` fail-closed；不支持硬链接的回退 `O_EXCL`。
- **I-6**：跨进程用例成功方持锁 5s，超时 kill 子进程。
- **I-7**：backlog 说明改为「受 iLink 契约限制」，不再声称已实现。
- **Minor**：`corrupt` 不可达分支加防御；`cli.js` 收紧为 `dist/` 下；6.2 接管 warn 补断言；`stop()` API 变更写入设计；验证脚本收编为 `scripts/verify-instance-lock.cjs`。
- **M-1~M-5**：需求 2.3/2.4/2.6/4.2 与术语表、设计 3.1 样例、属性 8/9、5.2 锁内容与文件名、架构图与常量名全部对齐实现。
