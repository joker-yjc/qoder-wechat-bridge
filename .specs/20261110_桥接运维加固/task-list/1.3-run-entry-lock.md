# 1.3 runService 双锁接入与释放

- 所属任务组：T1. 实例互斥
- 硬前置：1.1、1.2

## 目标

在 `runService` 启动链路中接入两层锁，保证"检查 + 登记"原子化；`run.json` 只在两把锁都拿到后写入；所有退出路径都释放锁；CLI 捕获冲突错误并输出中文提示。

## 实现要点

- 启动顺序：`ensureDirs` / `loadState` / 清理后先取状态锁 → **`run.json` 兜底（指向存活桥接进程则拒绝，陈旧则清理）** → 需要时登录并 reload config → 取 bot 锁（与状态锁共享 deadline）→ `createBridgeRuntime` → 预检 → `writeRunInfo()` → 主循环。
- 释放：`releaseLocks()` 幂等；**先 `cancelAllTasks()` 并 `waitForIdle()` 排空（上限 3s）再释放**，保证释放后不再写 `state.json`；`handle.stop()` 改为异步并 await 排空；一次信号交给 `runLoop` 收尾，二次信号 `exit(130)` 前直接释放；`runLoop().finally` 与启动异常 `catch` 同样释放。
- `createBridgeRuntime` / 预检 / `writeRunInfo` 一并包进启动 `try`，任一异常都摘早期信号监听并释放锁；`config.botId` 为空时记 warn。
- 拒绝启动路径 `log.error` 记录自身 pid、对方 pid、判定依据（锁 / `run.json`）与锁文件路径（需求 6.1）。
- `cli.ts` 的 `run` 分支捕获 `AlreadyRunningError`（调用 1.2 的 `describeOwner` 输出后 `exit 1`）与 `LockIoError`（输出路径/原因后 `exit 1`）。
- 审查现有 `service-startup` / `service` 单测：每次 `runService` 结束必须 stop 或走失败释放，避免锁残留导致后续用例失败。
- 新增单测：同一临时状态目录第二次 `runService` 抛 `AlreadyRunningError`；预写脏锁可成功启动；启动失败路径不写 `run.json`；`run.json` 指向存活旧实例时拒绝、陈旧时清理；预检抛错释放锁并摘监听；stop 期间锁保持在途任务结束后才消失；缺 botId 告警。

## 验收标准

- 触达文件 Lines 覆盖率 ≥ 95%；
- 拒绝启动路径不覆盖 `run.json`、不进入轮询；
- 释放后同一状态目录可立即再次启动；
- 释放锁后不再有 `state.json` 写入（排空用例断言锁在任务结束前仍存在）。
