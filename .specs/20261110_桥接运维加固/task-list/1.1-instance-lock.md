# 1.1 原子文件锁模块

- 所属任务组：T1. 实例互斥
- 硬前置：—

## 目标

新增 `src/bridge/instance-lock.ts`：用 `fs.openSync(path, 'wx', 0o600)` 原子获取两层锁（状态目录锁 + bot 级锁），提供脏锁接管、等待重试、幂等释放与两类错误。模块不读写 `state.json`、不发消息、不启动轮询。

## 实现要点

- 类型：`LockRecord`（`pid/ppid/startedAt/cwd/botId/stateDir/role`）、`LockHandle`（`release` / `paths`）、`AlreadyRunningError`（`owner` / `launchdLabel` / `waitedMs`）、`LockIoError`（`path` / `code`）。
- `botLockPath(botId)`：固定 `~/.local/state/qoder-wechat-bridge/instances/<sha1(botId).slice(0,16)>.lock`，**不随 `QWB_STATE_DIR` 变化**。
- `acquireInstanceLock`：`open 'wx'` → 写入 JSON → `close`；EEXIST 时读锁，**只有 `!isAlive(pid)` 才视为脏锁**并 `unlink`（ENOENT 忽略，最多重试 3 次）；存活（含命令行不匹配的保守情形）按 `pollMs=250` 等到 deadline 再抛 `AlreadyRunningError`；`deadline` 可由调用方传入以共享等待预算，`waitedMs` 为实际耗时；读不到内容的 `missing` 分支同样受 deadline 约束（`EBUSY`）；其他错误抛 `LockIoError`（message 含路径与错误码，fail-closed）。
- 拒绝启动时 `log.error` 记录自身 pid、对方 pid、判定依据（状态目录锁 / bot 锁）与锁文件路径；接管脏锁记 warn。
- 获取顺序：状态锁 → bot 锁；bot 锁失败时先释放状态锁；`botId === ''` 跳过 bot 锁并记 info。
- `release()` 先读记录，`pid !== process.pid` 直接跳过；重复调用安全。
- 依赖通过参数注入（`isAlive` / `isBridgeProcess` / `sleep` / `now`），默认取 `lifecycle.ts` 导出与真实 timer。
- 单测：同进程重复获取（防重入，注明不代表跨进程互斥）；`pid: 999999` 脏锁接管；损坏 JSON 接管；存活但命令行不匹配时不接管；共享 deadline 与真实 `waitedMs`；`missing` 分支 `EBUSY`；错误信息含路径；`open` 抛 EACCES → `LockIoError`；释放不删他人锁；`botId=''` 只建状态锁。
