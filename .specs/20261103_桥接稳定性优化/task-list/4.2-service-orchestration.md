# 4.2 service 接入 outbox 与 OutboundSession

- 所属任务组：T4. 服务编排与命令
- 硬前置：2.1、2.2、3.1、4.1

## 目标

重构 `service.ts` 的任务处理链路：所有出站走 `OutboundSession`，补发走 `outbox.ts`，qoder 失败走短错误；保留现有鉴权、媒体、命令、会话与 `/stop` 行为。

## 实现要点

- 为可测试性，把 `handleInbound` / `processTask` 收敛到导出的 `createBridgeRuntime(config, state, deps)`；`runService` 只负责启动循环、login、信号和 finalize。
- `RuntimeDeps` 至少包含：`sendText`、`runQoder`、`now`、`takePending`、`loadPersona`、`listModels`；测试可注入假实现。
- `processTask` 新顺序：
  1. `TypingKeeper.start()`；
  2. `ingestPendingNotices()`：把 `pending-notifications.jsonl` 全部写入 outbox，并按 `createdAt` 稳定排序；
  3. `pruneOutbox()`：TTL / 上限清理，记录被删除项；
  4. `flushOutboxForUser()`：用 `OutboundSession.budget` 按顺序补发；
  5. 内置命令 / 模型切换：走 `sendSingle`；
  6. `runQoder({ taskId, ... })`：失败 → `buildUserErrorReply` + `sendSingle`；成功 → `sendChunked`。
- 每个入站生成 `taskId`，传入 qoder 结果并写入 outbox 项。
- 保留现有：鉴权顺序、媒体下载、语音无转写提示、`/stop` 入队前处理、会话降级重试、`runningTasks`、typing。
- 不引入去抖；不修改 `chunkText` 行为。
- 额度连续告警：本轮命中 `quota` 则 `state.quota.streak += 1`，本轮有成功发送则归零；`streak >= 2` 写 warn。
- 出站日志包含 `messageId / taskId / category / chars / bytes / attempts`，不记录正文与 token。
