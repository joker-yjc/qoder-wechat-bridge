# 2.1 outbox 补发状态机、TTL、上限与隔离区

- 所属任务组：T2. 纯逻辑核心
- 硬前置：1.2、1.3

## 目标

实现设计 5.1.3 的纯逻辑队列状态机：根据发送结果决定删除、保留、跳过或隔离，并执行 TTL / 条数 / 隔离区清理。

## 实现要点

- 新增 `src/bridge/outbox.ts`，导出：
  - `DeliveryOutcome`、`OutboxPolicy`、`FlushResult`
  - `flushOutbox({ items, budget, policy, send })`
  - `pushOutbox(state, item, policy)`
  - `pruneOutbox(state, policy)`
  - `quarantineItem(state, item, reason, policy)`
- `flushOutbox` 规则：
  - `sent`：从结果中移除该条，`budget -= 1`；
  - `quota`：不增加任何计数，`stopReason='quota'`，当前及后续消息原顺序保留；
  - `session_expired`：不计数，`stopReason='session_expired'`；
  - `transient`：`transientFailures += 1`；达到 `transientMaxAttempts` 则隔离并继续，否则 `stopReason='transient'` 停止本轮；
  - `permanent` / `unknown`：`failures += 1`；达到 `poisonMaxAttempts` 则隔离并继续，否则跳过继续尝试下一条；
  - 预算为 0 时 `stopReason='budget'`。
- `pushOutbox`：追加后按 `outboxMaxItems` 丢弃最旧消息，返回 `dropped`。
- `pruneOutbox`：删除超过 `outboxTtlMs` 的 outbox 消息；隔离区超过 `quarantineTtlMs` 或 `quarantineMaxItems` 时删除；返回四类被删除项供 service 记日志。
- `quarantineItem`：从 outbox 移除，写入隔离区；`preview` 使用 `redactSensitive` 后截断 120 字。
- 所有时间通过 `policy.now()` 获取，便于测试。
