# 5.1 假 iLink + 假 qodercli 事故回归集成测试

- 所属任务组：T5. 集成与门禁
- 硬前置：4.2、4.3、4.4

## 目标

用可控的假 iLink 服务和假 qodercli，把 2026-11-03 事故链路完整跑一遍，验证修复后的端到端行为；不得调用真实微信通道或真实 qodercli。

## 实现要点

- 新增 `test/helpers/fake-ilink.ts`：本地 HTTP 服务，实现 `getupdates` / `sendmessage` / `getconfig` / `msg/notify*`；支持：
  - 入站消息队列；
  - `sendmessage` 按配置返回成功、`ret=-2`、`ret=-14`、HTTP 4xx / 5xx；
  - 记录所有出站文本与 `context_token`。
- 新增 `test/helpers/temp-state.ts`：创建临时 `QWB_CONFIG_DIR` / `QWB_STATE_DIR`，写入 config / state，测试结束清理。
- 扩展 `test/fixtures/fake-qodercli.mjs`：通过环境变量切换模式：正常 JSON、261KB stderr + 退出码 1、超时、空输出、`is_error`。
- 集成场景：
  1. **261KB stderr**：只发送 1 条 ≤300 字提示；outbox 为空；诊断文件 ≤64KB 且含 taskId。
  2. **毒丸隔离**：outbox 首条永久失败、后两条正常 → 后两条本轮送达；首条 3 轮后进入隔离区。
  3. **额度耗尽**：连续 `ret=-2` → 消息全部保留、顺序不变；下一窗口全部补发；`status` 显示连续告警。
  4. **会话过期**：`ret=-14` → 服务停止循环，消息保留。
  5. **TTL / 上限**：过期与超限清理生效，日志含摘要。
  6. **重启**：隔离区仍在隔离区；outbox 顺序不变。
  7. **预检失败**：只写日志 + 最多一条短告警；任务仍可执行并按需求 2 返回短错误。
- 使用 `runService(overrides)` 指向假服务；断言后调用 `handle.stop()`，避免测试挂起。
