# 3.3 stop 发现、冲突报告与手动提示

- 所属任务组：T3. qodercli 与运维
- 硬前置：1.2

## 目标

实现设计 5.1.8：`stop` 不再只依赖 `run.json`，能通过进程扫描和 launchd 标签发现实例；launchd 场景打印完整手动停止提示；多实例报告冲突。

## 实现要点

- 扩展 `src/bridge/lifecycle.ts`：
  - `planStop(input)` 纯决策：`idle / signal / supervised / conflict`
  - `listBridgeProcesses()`、`isBridgeProcess(pid)`、`findLaunchdServices()`
  - `parsePsOutput(text)`、`parseLaunchctlList(text)`、`parseLaunchctlPrint(text)`（纯函数，便于单测）
  - `formatStopOutcome(outcome)`：生成 CLI 输出文本
  - `stopService(waitMs?)`：发现 → 决策 → 信号 / 打印 → 验证
- 进程匹配同时覆盖：`qoder-wechat run`、`dist/cli.js run`；排除 `stop` / `status` 自身。
- launchd 场景输出：`bootout`、`launchctl print` 验证、`launchctl bootstrap` 恢复、`pkill -TERM -f "qoder-wechat run"` 兜底。
- 多实例 / 混合场景：停止 `run.json` 验证过的主实例（若有），其余列出并打印精确 `kill -TERM` 命令，退出码 2，明确报告冲突。
- 退出码：`idle` / `stopped` = 0；`timeout` = 1；`supervised` / `conflict` / `EPERM` = 2。
- Windows 仅按 `run.json` 处理，不调用 `ps` / `launchctl`。
