# 3.1 runQoder 错误分类、短错误与诊断接入

- 所属任务组：T3. qodercli 与运维
- 硬前置：2.2、2.3

## 目标

改造 `runQoder`：失败时不再把原始 stdout / stderr 返回给上层，而是写入诊断文件并只返回 ≤300 字短错误；同时补齐错误类别、退出码和 taskId 关联。

## 实现要点

- `QoderRunInput` 新增必填 `taskId`、可选 `diagnosticDir`。
- `QoderRunResult` 新增 `errorKind`、`exitCode`、`diagnosticPath`；`error` 改为短提示。
- `finalize` 失败顺序：
  1. 超时 → `timeout`；
  2. `child.on('error')` → `spawn`；
  3. stdout / stderr 都为空 → `empty`；
  4. 无法解析 result → `parse`；
  5. 退出码非 0 → `exit`（即使解析出 result 也按失败）；
  6. `is_error=true` → `is_error`。
- 上述失败都先调用 `writeDiagnostic`（2.3），再通过 `buildUserErrorReply`（2.2）生成短错误；不把 stdout / stderr 原文放进 `error`。
- stdout / stderr 缓冲按 **字节** 累计，上限 5MB；解析时仅当输出 ≤1MB 才尝试整段，否则只尝试最后 200 行，避免对超大源码逐行 `JSON.parse`。
- 保留现有 `parseResult` 匹配规则与 `cleanEnv` 行为，不扩大范围。
- `src/index.ts` 导出新增类型。
