# 1.1 注册表枢纽 + 处理器接口 + 分发

- 所属任务组：T1. 命令注册表骨架与既有命令迁移
- 硬前置：—

## 目标

建立统一的命令处理器注册表与单一分发入口，使新增命令只需新增处理器模块并登记一行，不改分发主干。本任务只立骨架与接口，既有命令迁移在 1.2、service 接线在 5.1。

## 实现要点

- 先写失败单测：`findHandler` 前缀匹配（`/switch` 与 `/switch 2`）、`dispatchCommand` 命中/未命中返回布尔、`COMMANDS` 由处理器 `def` 派生、`isUnknownCommand` 识别已登记命令。
- 新建 `src/bridge/commands/types.ts`：`CommandContext`（userId/contextToken/state/config/reply/workdir/persistState/catalogs/pendingNames/isTaskRunning/deps/log）与 `CommandHandler`（def/requiresIdle?/handle）。
- 重构 `src/commands.ts` 为注册表枢纽：`COMMAND_HANDLERS: CommandHandler[]`（初始可空，1.2 起填充）、`COMMANDS = COMMAND_HANDLERS.map(h => h.def)`、保留 `formatHelp`/`isUnknownCommand` 行为、新增 `findHandler(text)` 与 `dispatchCommand(ctx, text)`。
- `findHandler` 按 `text === name || text.startsWith(name + ' ')` 匹配；`dispatchCommand` 命中则 `await handle` 返回 true，未命中返回 false。
- 类型用 `import type` 避免运行时循环依赖。
