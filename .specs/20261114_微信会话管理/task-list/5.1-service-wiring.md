# 5.1 intake 守卫 + 注册表分发 + 上下文 + 内存态

- 所属任务组：T5. service 接线
- 硬前置：1.2, 4.1, 4.2, 4.3, 4.4, 3.1

## 目标

把注册表接进 service：intake 元数据守卫、`dispatchCommand` 替换 if 链、组装 `CommandContext`、内存缓存/待用名、创建时消费待用名。这是全链路收口，依赖全部处理器就绪。

## 实现要点

- 先写失败集成单测：任务运行中 `requiresIdle` 命令被拒不入队；`/sessions` 仍入队；无任务正常入队；`dispatchCommand` 命中四新命令与既有四命令；创建时无 sessionId + pendingNames → runQoder 传 `name`，成功写指针后清 pendingNames；普通消息/`/reset`/`/status`/`/model`/`/stop`/`/help` 黄金路径不回归。
- `service.ts` 导入注册表（`dispatchCommand`/`findHandler`）与 `sessions.ts`；deps 注入 `listSessions`/`renameSession`（照 `listModels` deps，service.ts:73/212）。
- 新增内存态 `sessionCatalogs = new Map<string, SessionEntry[]>()`、`pendingNames = new Map<string, string>()`。
- intake（service.ts:896 `/stop` 块后）：`findHandler(commandText)?.requiresIdle && runningTasks.has(from)` → `sendControl` 拒绝并 return；守卫由元数据驱动，不硬编码命令名。
- `processTask`（service.ts:500 起）：if 链替换为 `const handled = await dispatchCommand(ctx, command); if (handled) return;`，保留其后 `isUnknownCommand` 与 runQoder；组装 `ctx`（reply 包 `session.sendSingle`，workdir/persistState/catalogs/pendingNames/deps/log）。
- runQoder 调用处（service.ts:575 起）：`!state.sessions[userId]?.sessionId && pendingNames.has(userId)` 时传 `name`；成功写指针（service.ts:654）后 `pendingNames.delete(userId)`。
- `/stop` 保留 intake 快速路径，不入注册表（N1）。
